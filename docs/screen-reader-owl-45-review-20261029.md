# フクロウ4・5番：姿と戦闘対象の引き継ぎ

基準main `e00334de`。利用者の診断432件では1～3番の自動撃破3件が成功し、4番HP10→6→2、5番HP10→1は保持するが最後の撃破を反映しない。履歴削除0件。

## 原因と変更

元動画の約13～14秒（5番）と49～50秒（4番）を目視確認した。既存版のNative Canvas解析は5番の短い一部で灰を認識し種類候補を出すが、4番は灰0件。両者の可視部分から8枚を追加し、倒れた後半の姿も照合できるようにする。採用上限0.14・種間差0.025とグレー→光の時系列条件は変更しない。取得周期を変更したり全OCRの負荷を増やす処理も追加しない。

また、イベント表の秋幻フクロウ累計は4体だが、診断台帳には番号5まである。従来の `台帳数 === 実行済みイベント累計` 条件では、追加の番号付き生存個体が確認できていても全フクロウの戦闘対象が保留になる。イベント数を必要最低数として扱い、台帳にその数以上の個体があり、全員生存観測済み、1～台帳数まで重複・欠番なしの場合だけ個体対応に使う。イベント予定から個体を足さず、画面の見掛け上の1体だけで確定しない。なぜ5番が存在するか（ゲーム内の追加出現・番号体系等）をこの変更で断定しない。

出現数が不足する場合、未確認・欠番・重複・無効な内部IDや最大HPの場合は保留。60秒のHP保持・45秒の戦闘保持・復帰2.5秒、残った生存ラベル拒否・マップ／難易度の照合・Undoは維持する。初期singleton経路はイベント数と台帳個体数の両方が1の場合に限定し、他の確認済み個体の記憶が失効していても見掛け上の1体へ確定しない。

## 追加で残る制限

5番は診断の経過319.915秒でHP1/10の記憶が60秒期限切れになり、323.730秒にフクロウ開始カット、325.545秒に戦闘対象未確定、335.603秒に番号保留となっている。この335秒付近は新動画の最初の5番撃破に対応する。候補欄に4番があることだけで4番の撃破と解釈しない。

今回の補正は新鮮な番号観測がある場合の対象保持と形状の改善まで。5番のこの実記録では期限切れもあるため、同じ条件で番号付き自動反映が必ず成功するとは扱わない。期限切れを与える否定回帰を追加し、残った4番へ誤って付け替えないことを確認する。戦闘中のHPから再同定するか、過去の個体記憶と後続の生存観測を安全に照合する処理は後続課題。古いHPをそのまま新鮮な位置・対象の証拠へ昇格させない。

素材フォルダは `tests/fixtures/screen-reader/defeat/autumn-owls-45-20261029/`。全約54秒の匿名化・原寸切り出し確認動画、96フレームの局所シート、8可視パッチ、戦闘画面、入力・出力ハッシュと元PTSを保存。原115MB・全画面・音声は保存しない。

250ms取得周期の開始位相10通りで2体とも番号付き候補を1回ずつ取得。番号とHPを明示的に事前観測として渡す契約試験であり、同じ原動画から番号を自動OCRしControllerへ通した成績ではない。出現数不足・未確認個体・欠番・最大HP不一致・追加個体がいる場合の単独候補の各10位相は番号付き確定0件。Native Canvasで確認し、Chromium/WebKitで既存1～3の見本回帰・通常の番号付き反映と合わせて検証する。最終CIとマージ状態は同PRを参照。
