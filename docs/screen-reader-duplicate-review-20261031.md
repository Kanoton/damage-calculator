# 撃破候補の衝突と保留理由

基準main `88a8dfd7`。保存済みフクロウ4・5番の96局所フレームを全フレーム順にブラウザで再解析し、種類候補が出た元フレーム番号・PTS・範囲をCIログの `OWL_DUPLICATE_REVIEW` とartifactに記録する。これは見本を含む開発回帰であり、原動画全体の番号OCRや未知動画の精度ではない。

同じ位置・短い間隔の候補が同じ演出の続きか、重なった別個体の撃破かは時刻・範囲だけでは確定しない。種類候補は削除しない。最後の衝突後に全ての他候補の生存を改めて2回確認できた場合だけ、残る一体を確定できるようにする。2体以上が未確認なら引き続き保留する。

## 変更

- 同種の未確定候補に次の演出候補が来ると `multiple_defeat_candidates` を記録。最初の灰時刻・光時刻・範囲、後の候補の同じ情報、候補数を保存する。範囲は既存の正規化1536×710基準。時刻はtrackerへ渡した経過時計のmsであり、ISO日付ではない。
- `possibleRepeat` は範囲が重なり、最初の光から1.8秒以内という調査用のフラグ。別撃破でもtrueになり得るので、自動統合や番号確定の根拠にはしない。最初の証拠と最新の衝突だけを保持し、無制限の画像・候補配列は追加しない。
- current.unresolvedへ `holdReason`、`cueCount`、`evidence`、`lastCollision` を追加。blockedの場合は表示状態も複数候補での保留とする。通常の候補は `survivor_wait`、生存を2回読んで除外した個体は `survivor_confirmed` として履歴へ残す。
- 候補衝突のたびに、それまでの生存除外を消去。最後の衝突より後の連続2観測だけを使い、他候補全員の生存で残り一体へ絞れたとき `survivors-after-collision` で一度だけ確定し、`collision_resolved` を記録する。古い衝突前の生存確認を流用しない。
- その他の撃破候補・自動反映条件、5秒／30秒、灰→光、全出現数、内部ID／最大HP、reset、Undoは変更しない。JSON version 1は互換的に拡張する。

## 検証

既存の保存実画素＋明示的な番号観測の契約試験を拡張。同じ場所に65250msの灰→65750msの光、66000msの灰→66250msの光を与え、他候補が全員生存なら残る5番を1回だけ確定する。別の契約試験では生存中4・5・6の3体から2候補が出たあと4番だけが生存確認できても、5・6の2体が残るため確定0件。最初と次の時刻、候補数2、possibleRepeat=trueも記録する。近い時刻・同じ範囲だけでは統合しない保護の試験であり、実際の別個体2体をOCRした素材ではない。正常な生存確認と残り14保留条件も維持する。

保存済み4・5番の再解析は各ブラウザで元PTS付きの全候補を保存し、両方の場面でフクロウ・番号未確認の候補が得られることを確認する。件数の減少を認識改善と取り違えず、同じ演出が繰り返される場所を後から比較できるようにする。

残課題：同一演出の継続を示す画素の連続性、間に色付き生存姿が挟まる場合、同種が重なって連続撃破される場合を対比し、安全に統合できる条件を追加する。今回解消できるのは全ての他個体の生存を衝突後に確認できる場合で、画素だけによる自動統合は未対応。最終の再解析結果、CI、マージ・公開状態は同PRを参照。

衝突前の4番生存を除外に使った後、次の衝突で除外を消去し、衝突後に5番だけを生存確認しても4・6番が残るため確定しない回帰も追加する。
