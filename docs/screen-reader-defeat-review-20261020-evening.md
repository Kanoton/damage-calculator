利用者の「フクロウ3体・恐竜1体を1ターン中に撃破したが反映されない。直前HPの保存も確認してほしい」という報告を調査した。基準mainは `00380224d93fa77de4dd1edec42f0529620000eb`（#244）。今回の変更は調査記録のみ。アプリ・辞書・閾値は変更していない。

## HPは保存できるのか

`ScreenReaderWorldVision.analyze(normalize(frame),{positions:true})` の観測列へ、実装中の `accept` / `stabilize` を取り出して適用した。初期のフクロウ3個体の8/8と恐竜の19/19は連続採用を通過。恐竜は約66.4秒に12/19、約66.6・66.9秒に5/19を採用する。

`MapBridge.apply(...,{allowDefeat:false})` は、マップ・難易度・最大HPが一致すれば正のHPを個体へ保存する実装。HP0は引き続き撃破に適用しない。一方、撃破用の位置記憶 `identities` は別で、恐竜の攻撃中はcount=1のまま、約67.1秒には空になる。HPが読めても演出へ結び付ける記憶が残らない。

今回のゲーム動画には利用者のブラウザ内部の保存状態・設定が含まれないため、実機で5/19が保存されたとは断定しない。確認したのは読取器、連続採用、保存コードであり、実ControllerとMapBridgeの動画連続実行を成功済みと扱わない。

## 止まっている箇所

1. **部分形状の見本不足。** 暗い連結部分は検出するが種類の分類を通過しない。フクロウの約36.9秒の最良距離は約0.162（閾値0.14）。恐竜の約67.4秒は領域 `[264,124,87,90]`、面積4153を検出するが恐竜の距離は約0.352。重なり・姿勢の異なる今回の形状に対応していない。全種類の閾値を一律に緩める修正は避ける。
2. **攻撃中の位置追跡が成立しない。** 恐竜の線の先端は約66.1〜66.9秒に `[631.5,339]` → `[570,302]` → `[625,339]` → `[600,320]` と揺れ、背景連続性も4回ともfalse。毎回記憶が消去され、2回連続の安定条件を満たさない。座標は1536px popup平面。背景判定falseの原因を全て実際のカメラ移動と断定しない。
3. **長期の個体記憶が未接続。** 現行の位置記憶は1.2秒で、戦闘画面への切替でも消える。フクロウ1・2番は戦闘後の演出を事前の個体へ戻せない。フクロウ3番も直前の名前・番号・8/8は連続取得するが、本体への線の先端は未判定。
4. **確定した出現数を使っていない。** 正本の秋幻・進捗1は恐竜1体＋フクロウ3体。恐竜1番と19/19も実際に読めているため、確認済み進捗・出現履歴と既読個体を保持する経路が有効。ただし現行にはない。画面に偶然1体しか読めなかった場合と区別する。

## 次の修正と回帰

- マップ・難易度・出現世代・内部個体IDごとの番号と最終HPを、短期の座標記憶から分離する。リセット・新規出現・番号再利用・矛盾する生存観測を扱う。
- 恐竜は確認済み進捗1の出現数1、番号付き生存確認、該当種の撃破演出を組み合わせる。HPや一覧の見掛け上の単一候補だけで撃破しない。
- 攻撃時の線の誤追跡・前景変化と背景移動を区別する。期限を延ばすだけで古い座標へ帰属させない。
- 今回の姿勢・重なりを含む可視部分の演出を改善する。全身一致は必須にしない。出現光、キャラ自身の撃破、途中のフクロウ6/8生存を負例にする。
- 戦闘開始対象と戦闘終了を保持し、4撃破と途中の生存を実Controllerの異なる連続フレームで検証する。静止した事前画像の反復や見本内の成功を動画全体の成功率と扱わない。

## 計測方法と限界

`ffmpeg -i INPUT -vf fps=4 -c:v libwebp -lossless 1 -compression_level 0 -f image2 o%04d.webp` で原寸を維持。37〜384枚目を現行normalize・world reader・defeat trackerへ順に渡した。追跡器は冒頭1回だけ初期化。観測時刻はfps区間中央の公称時刻で、元動画の正確なフレームPTSではない。途中で行った事前縮小の予備確認は最終結果へ含めない。

追跡器の診断用コピーへ、純関数sceneStableの結果とidentities/pendingの読み出しだけを追加。分類・閾値・候補条件・観測は変更していない。実装から取り出したaccept/stabilizeも同じ観測列へ適用。主要結果・ソースのハッシュは [診断JSON](screen-reader-defeat-review-20261020-evening.json)。共有画面の実測、ブラウザによる動画連続実行、未知動画の精度評価ではない。

以前のCI成功は保存見本と限られた番号付き場面の回帰であり、今回の4撃破が動く保証にはならなかった。次回は今回の失敗を再現する連続動画の回帰から修正する。
