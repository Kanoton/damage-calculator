# 期限切れ後の個体番号と、後続の生存確認

基準main `5a95d6ce`（PR #262をマージ）。#262は形状8枚と追加番号の台帳照合を改善したが、フクロウ5番の実記録では戦闘前に短期HP記憶が60秒で期限切れになっていた。古いHP・位置を新しい戦闘対象の根拠にせず、番号の記録だけを別に保持する。

## 実装

- `knownIndividuals` に、実際に正のHPと番号を確認した個体の種類・番号・内部ID・最大HP・最後に読めたHP・観測時刻を保持。位置やラベル座標は持たない。HP値は `lastSeenHp` として扱い、現在HPと表示しない。
- 60秒のHP／位置記憶、戦闘対象の直前2秒・保持45秒、部分グレー→消滅光の1.8秒、マップ復帰2.5秒は維持する。番号の台帳だけで戦闘対象・単独個体・撃破を確定しない。
- 種類の撃破演出が成立し、実行済み出現数・全員の生存確認・連番がそろい、生存中の全候補を過去に個別観測している場合に限り、候補を保持する。
- 候補に短期記憶が切れた個体が含まれる場合、最大30秒、他の候補の正のHPを連続2回読み取るのを待つ。全ての他候補の生存が確認でき、一体だけ残った場合にその番号へ対応付ける。例えば5番の撃破演出を保留し、約18秒後に4番HP6等の生存を2回確認すると、5番と確定できる。
- 記憶が新鮮な場合の従来の後続生存照合は5秒のまま。30秒の不在だけでは確定しない。2件目の同種未確定演出が来た場合は対応付けをブロックし、同じ生存個体を使い回さない。
- 演出時の同種台帳（番号・内部ID・最大HP・撃破／確認状態）を固定して照合し、待機中に増援や別個体が追加された場合は特定待ちを破棄する。
- 同じ台帳内だけで保持し、撃破済み・内部ID差し替え・最大HP不一致・未確認状態で破棄。新ゲーム・共有停止・独立画像・マップ／難易度／ルート変更など既存のresetで全消去。取得間隔1.8秒超では演出・特定待ちを破棄し、番号の記録を新鮮な追跡に昇格させない。保持数は現在の台帳個体数に制約される。
- JSONのcurrentに `knownIndividuals`、unresolvedに `archived`／`timeoutMs`、履歴に `archived_candidates` を追加。コピー独立性を保ち、既存のversion 1を互換的に拡張する。番号確定のassociationは `archived-survivors`。既存MapBridgeが番号・内部ID・最大HP・生存状態を再検証し、同じ撃破操作／Undoを用いる。

## 検証と限界

保存済みの実フクロウgray／beam画素と、番号4・5／HP6・1の明示観測を使う。65秒で短期記憶を失効させ、撃破演出から約18秒後の別候補の生存2回で5番を確定する契約試験。原動画から番号をOCRした実測ではない。

生存確認なし・1回だけ・二重観測の矛盾・当人も生存・未観測の候補・出現数不足・増援による台帳変更・reset・取得切れ・30秒超・内部ID差し替え・最大HP違い・同種2演出では番号付き確定しない。古いHPが小さい順に選ぶような処理はない。既存の5秒での保留、未知画像、番号付き反映とUndoの回帰も維持する。ブラウザの最終CI・マージ状態は同PRを参照。

同じ演出中に種類候補が複数回出ることがあり、別の撃破か区別できない場合は今回も保留する。全ての取得位相での5番自動反映や、同じ原動画全体を通常Controllerに通した認識率を保証したものではない。利用者の同一リプレイでの再確認は必要。
