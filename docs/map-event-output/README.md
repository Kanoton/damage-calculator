# 動画からマップイベント情報を出力する

この資料は、動画を受け取ったAIがリポジトリ内のデータを参照し、CSV・マップ図・ZIPを作成するための手順です。別のチャットでも、このリポジトリと動画を渡せば同じ出力方針を引き継げます。

## 利用者の渡し方

動画のファイル名は、例えば `異変図書館_普通_01.mp4` とします。同じマップ・難易度で2回撮影した場合は `01`、`02` 等で区別してください。通常速度・10倍速、音声あり・なしのいずれも受け付けます。10倍速への再変換は不要です。

このプロジェクトを参照することが分かっている会話では、動画だけの添付をマップイベント解析の依頼として扱います。新しいチャットにプロジェクトの参照先が伝わっていない場合は、最初に次の文と動画を渡してください。

```text
https://github.com/Kanoton/damage-calculator の AGENTS.md と
docs/map-event-output/README.md に従って、添付動画から
map_event.csv用の候補CSVとマップイベント図を出力してください。
マップ名と難易度は動画のファイル名を参照し、不明なら確認してください。
```

GitHubに動画を登録する必要はありません。動画はその会話に添付してください。リポジトリに保存するのは手順・素材・サンプルです。動画をアップロードするだけでGitHub Actionsが自動認識する仕組みではありません。

## 最初に確認すること

1. `AGENTS.md`、`WORKING_GUIDE.md`、`docs/development-handoff.md` とこのファイルを読む。
2. ファイル名またはフォルダ名のマップ名・難易度を、正本CSVに照合する。別名があっても一意に対応できなければ確認する。
3. **マップ名または難易度が欠ける・曖昧・画面と矛盾する場合は利用者へ確認する。前回の「普通」を既定値にしない。** 判読可能な映像の抽出等は先に進めてよいが、対象を推定して確定CSVへ出力しない。
4. 対象マップのベース画像、関連イベント図、モンスター画像、IDを探す。不足や所在不明は必要なファイル名・用途を具体的に報告する。
5. 確認済みの入力条件と、解析に使用したリポジトリのコミットSHAを記録する。

## 動画の読み取り

進捗は**画面中央上部の数値・イベントアイコンの列**を使用します。左上のRound番号は使いません。イベント発生箇所は数値が同じアイコンに置き換わるため、前後の数値と列内の位置から進捗を割り当てます。判別できなければ保留にします。分岐時・ボスHP半分などの条件は数値へ無理に置換せず、CSVと同じ条件表現を使用します。

### ゲームオーバーの進捗（末尾の赤い×）

**中央上部の進捗列の最後にある赤い×は、そのマスの進捗でゲームオーバーになることを示します。** ×は数値の代わりに表示されます。直前の数値と同じ列のマス順から読み取り、17の次の1マスが赤い×なら終了進捗は18です。×以降の装飾や終端の色付き部分は追加の進捗として数えません。左上のRoundや動画の最終フレームの現在進捗を終了進捗にしないでください。

数値・×がカメラやUIで隠れる場合は別の時刻の表示を確認し、動画内で×と隣接数値が読める根拠画像を残します。推定方法と、×の直前の数値・間のマス数を観測JSONへ記録してください。読み取れない場合は未確定として報告し、既存CSVの終了進捗を今回の動画の観測値として代入しません。

利用者は、すべての進捗イベントが発生し、終了進捗が確認できたところで録画を途中終了することがあります。**赤い×の表示から終了予定を確認できれば、実際の終了場面が録画されていなくてもゲームオーバー行を出力します。** 「終了進捗の表示を確認した」と「その進捗に到達してゲームオーバーが発生した」は区別して記録します。録画が早く終わることだけを理由に終了進捗を保留にしたり、再録画を要求したりしません。新しい動画のイベントが実際にすべて読めたかは別途確認し、不明なものだけ報告します。

今回の異変図書館・普通は、利用者が提供した画面の中央上部に12～17の数字と、その次の赤い×があるため**進捗18でゲームオーバー**と確定しています。根拠の切り抜きは `samples/library-normal/evidence/progress18_game_over.png` です。

まず全体を確認して、通知・出現演出・進捗の変化を探します。通知付近は密にフレームを抽出し、中央上部と通知文を元解像度で拡大してください。一定間隔の静止画だけで「イベントがない」と判定しないでください。動画を読む機能やフレーム抽出環境が使えない場合は、その制約を報告し、動画を解析済みと装わないでください。

FFmpegが使える場合の抽出例（パスと時刻は入力に合わせる）：

```sh
# 全体の確認用。10倍速でも短い通知はこの抽出から漏れる場合がある。
ffmpeg -i "異変図書館_普通_01.mp4" -vf fps=2 "frames/%06d.png"
# 通知付近を0.1秒ごとに確認する例。提出された動画上の時刻。
ffmpeg -ss 24 -i "異変図書館_普通_01.mp4" -t 3 -vf fps=10 "detail/%06d.png"
```

事前に `frames`、`detail` を作成してください。FFmpegがなければ、環境で利用可能な動画デコーダーを使って構いません。出力の時刻は提出動画上の時刻として記録し、元のプレイ時間との変換は倍率が明示された場合だけ行います。

各イベントについて、進捗／条件、ルート、モンスターの種類・ID・出現数、攻撃／防御加算、出現位置、固定／ランダム、根拠となる時刻・画像を記録します。出現数はそのイベントでの**新規出現数**です。画面に残る既存個体や初期配置を重複計上しないでください。

座標はゲーム画面のピクセル座標をそのまま貼り付けず、マスの種類・隣接順・分岐・初期位置との相対関係からベース画像のマスに対応付けます。カメラ移動・ズームを考慮し、追跡できないマスは保留にします。画面外がない自動カメラ設定は今回の録画で利用者が指定した条件です。将来の全動画に自動適用せず、映っていない情報が必要なら報告します。

既存CSV・図と一致していても「動画だけで確認した」と書かず、動画確認、参照補完、利用者承認を区別してください。既存資料だけでは新規の動画のイベントを観測したことになりません。

## 固定・ランダムの扱い

利用者の明示、既存の承認記録、または比較動画の結果を根拠にします。同じマップ・難易度・ルートを2回プレイして内容と場所が同じなら、利用者の方針に従って、その観測範囲では固定として扱えます。「2回一致」をゲーム全条件におけるランダム不在の証明とは記録しません。異なる場合は条件差とランダムのどちらかを確認します。

1回の録画だけで未承認の固定／ランダムを断定しません。未確定のものへ「ランダム出現」を付けません。**今回のMAP0104・普通はランダムなしと承認済み**であり、ランダム表示を作成しません。この条件を別マップへ引き継がないでください。

## CSVの出力

列順はその時点の `csv/map_event.csv` を正とします。現在は以下の10列です。

```text
map_id,route_id,難易度,進捗,monster_id,出現数,内容,攻撃加算,防御加算,出現位置画像
```

複数モンスターのIDと数量を同じ順で `|` 区切りにします。今回確認した難易度だけを出力し、他難易度へ無条件に広げません。出現と全体強化は別行にして、進捗4・10の全モンスターA+1/D+1は今回承認されたCSVのとおり記録します。ゲーム内の適用順序を追加の保留理由にしません。計算アプリの処理順を変更する依頼ではありません。

確定行は `map_event_candidates.csv`、未確定行がある場合だけ `map_event_pending.csv` をUTF-8 BOM付きで作成します。既存の同一イベントは単純追記すると重複するため、マップ・ルート・難易度・進捗と出現／強化行の区別を照合して更新候補を提示します。正本に複数難易度共通の行がある場合、普通だけの結果でその行全体を書き換えません。

ゲームオーバーは出現・強化と別の1行にします。`進捗`に×から読み取った数値、`内容`に`ゲームオーバー`、`monster_id`と`出現数`と`出現位置画像`は空欄、`攻撃加算`と`防御加算`は0です。終了のためだけのマップ図は作成しません。今回の行は以下です。

```csv
MAP0104,,普通,18,,,ゲームオーバー,0,0,
```

この行を加えた今回の候補CSVは、出現4行＋強化2行＋ゲームオーバー1行の計7行です。既存の正本にも普通・困難の進捗18の行がありますが、今回確認した普通だけを候補に記録します。

動画解析の依頼では成果物を出力し、GitHubの正本CSV・アプリ内フォールバックを自動更新しません。反映を別途依頼された場合に、参照画像・フォールバック・関連テストも含めて更新します。

## マップ図の出力

固定出現は**緑枠だけ**を該当マスに重ねます。モンスターの立ち絵・アイコン・IDのラベルを追加しません。元のマス種別アイコンと1st～4thは維持します。枠は素材を原寸で中心へ合わせ、異なる縮尺が必要なら元画像との比例関係を確認して処理します。補助スクリプトは原寸描画です。

ランダムと確定したイベントは、マップへ `Random.png` を重ねます。枠内へモンスターを追加しません。位置は該当マップの見本を優先し、なければ空白へ配置します。固定とランダムが混在する場合は、固定分のみ緑枠にし、ランダム分にラベルを付けます。

イベントごとに透過PNGを出力し、ベース画像のサイズを維持します。ファイル名はマップ・難易度・進捗／条件が区別できるものにし、候補CSVの画像名と一致させます。緑枠は位置を示す表現であり、座標が動画単独で検証済みという意味ではありません。

オレンジ破線の参考図がある場合は無変更で `reference/` に残し、緑枠図とは分けます。新しい参考図が必要なら、位置の確度と根拠を示し、未確認位置を確定図へ混ぜないでください。

## 再生成用スクリプト

このスクリプトは、AIが動画を読み取り終えた**観測JSON**を入力とする描画・CSV作成用です。動画認識・OCR・ゲームルール判定は行いません。利用者がJSONを手で準備することを前提にせず、動画を受け取ったAIが作成して実行します。

```sh
python3 -m pip install -r scripts/requirements-map-event.txt
python3 scripts/map_event_output.py \
  docs/map-event-output/samples/library-normal/observations.json \
  --output /tmp/library-normal-output
```

出力先は存在しないフォルダを指定します。同名のZIPも上書きしません。JSONは保存済みサンプルを参照してください。

- トップレベル：`map_id`、`difficulty`、`route_id`、`base_image`、`events`、`notes`、任意の`reference_images`。
- イベント：`status`（`confirmed`／`pending`）、`progress`（数値または条件）、`content`、`monsters`（`id`と`count`）、`attack_bonus`、`defense_bonus`。
- 図：`spawn_mode`（`fixed`／`random`／`mixed`／`none`）、`image`、`positions`（ベース画像のマス中心座標）、`position_source`。位置不明は図を付けず`pending`で保留可能。
- ランダム表示：`random_label_xy`（ラベルの左上座標）。ランダムのみのイベントに固定マス座標は指定しない。
- 根拠：任意の`evidence`や観測時刻をJSONへ記録でき、出力ZIPにJSONごと保持する。通知の切り抜き画像等はAIが追加する。
- ゲームオーバー：`kind: "game_over"`、数値の`progress`、`content: "ゲームオーバー"`、空の`monsters`、`spawn_mode: "none"`、空の`image`、攻撃・防御加算0とする。`kind`は観測JSONの分類用でCSVの列を追加しない。`evidence`に赤い×の直前の数値、×までのマス数、表示画像、表示から予定進捗を読んだ根拠を記録する。

例：ランダムと確認されたイベントにだけ、実際のID・数量とともに以下を設定します（これは図の指定例で、イベントの確定データではありません）。

```json
{
  "spawn_mode": "random",
  "image": "対象マップ_対象難易度_対象条件_random.png",
  "random_label_xy": [211, 535],
  "positions": []
}
```

## 最終確認と納品

CSVの列数、IDと数量の対応、難易度、画像ファイル名、図のサイズ、枠の位置・欠落・はみ出し、ランダム判定を確認します。マップ図は実際に開いて見た目を確認してください。ZIPを展開検証し、CSV、MapEvent図、観測JSON、参考図、通知の証拠、未確認事項の報告をまとめて返します。未確認情報を確定CSVへ混ぜず、読めた分の出力は先に完成させます。

必要素材が足りない場合は、例えば「対象マップのベース画像が `images/Map/` に見つからない」「表示名に対応するmonster_idが `monster_stats.csv` にない」と具体的に報告してください。同じ素材が既にある場合は再提出を求めず、その保存先を使います。
