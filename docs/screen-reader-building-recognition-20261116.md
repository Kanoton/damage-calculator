# 08：秋幻の森の植物建築・ゲーム画面読取（試作状況）

2026-11-16。対象は `08_screen_reader` のみ。**この変更は自動認識の完成ではありません。**

## 目標

- `csv/map_building_slots.csv` の16個のスロットと画面中の建築済み植物を対応付ける。
- 6種（電流タンポポ・芳香ピーチ・花咲くサボテン・金運の木・仙果スターフルーツ・疾走キノコ）を区別し、該当スロットの外側植物枠へ表示する。
- カメラ移動・画面外・人物やHUDによる遮蔽・建築前の空き枠・元のマスがショップ等へ置換された場合にも誤った上書きを行わない。
- 他プレイを混ぜない。共有切替、マップ/難易度切替、停止、リセット、Undo、file://、PC縦横への対応を保つ。

## 今回実装した境界

`08_screen_reader/js/autumn-buildings.js` に `applyRecognized(result)` を追加し、`window.ScreenReaderBuildingBridge` 経由で呼べるようにした。検証可能な候補に限り追加し、手動配置との競合・存在しないマスID・重複マス・未知種・低信頼・連続観測不足・マップ/難易度不一致・視点未照合を棄却。画面に写らない建物を「未設置」と判断せず、撤去も行わない。正当な複数追加をまとめてUndoの1単位にする。既存の手動選択、06/07、正本CSVは変更しない。

**画面画像から観測候補を生成する認識器は未接続**。現時点で画像を渡してもこのAPIが自動的に呼ばれるわけではない。誤解を避けるためUIには「自動認識対応済み」と表示しない。

## 提供画像の試作照合と限界

2026-11-15/16に提供されたゲーム画像を、画像そのものをGitHubへ保存せずローカルで検討した。

- 6枚を視点の基準にし、ゲーム盤面から得た少数の縮小特徴を照合する試作では、同じ6枚への再入力は一致した。
- 別の7枚のカメラ位置・ゲーム状態では、事前に固定した厳しい一致基準に届かず、すべて保留。これは別視点の自動対応や新しい建築種類の検出性能を実証しない。
- 現行の目視位置対応には推定が残り、例えばユーザーが明示確定した「I12はイベントからショップに置換」と、他の画像からの推定は証拠の強さが異なる。推定ラベルを自動教師データにしない。
- 3ゲームのスクリーンショットの建築状態を合算しない。

## 追加検証：リプレイ2本（2026-11-16）

- ユーザー提供の10倍速リプレイ2本（約82秒・約81秒）を、別ゲームとしてローカル解析。元MP4と個人名入り静止画はリポジトリに含めない。
- ORB特徴点で旧スクリーンショットとリプレイ①の約26秒を照合すると、植物鉢が連続する区画で、**高い特徴点一致数でも1マスずれてしまう**結果を確認。画面全体のホモグラフィ推定だけではスロット確定として扱えない。
- 読取を安全側にするため、異なるアイコン種のマス（雷・移動・モンスター等）をランドマークにして検証。リプレイ①の25.8秒と26.0秒は雷・移動の2点が類似度約0.77で整列し、O31/O32/O33の候補位置を得た。両フレームは異なる画像だが、第三の独立目印が確認できず **登録禁止の候補**。さらに建築植物の見た目は参照スクショと時点が異なるため引き継がない。
- リプレイ②で選んだ6時刻では、上記参照視点への一致なし。未登録視点に対する保留が必要。
- `scripts/review-autumn-building-replay.py` と `docs/screen-reader-autumn-building-anchors-example.json` に、プライベートな動画をアップロードせずに検証するオフライン研究用の入口を追加。OpenCV/numpyは研究用であり、08ブラウザのランタイム依存ではない。**本番の自動認識実装ではない**。
- 検証上の結論：種類を決めるには参照画面の植物をそのままコピーせず、現在フレーム内の植物を独立分類する必要がある。類似マスの区画誤認を除去するには、異種マスの3点照合・幾何検証が必要。現状いずれも満たせないフレームは保留する。

## 追加検証：三点幾何検査と独立フレーム（2026-11-16）

- `scripts/review-autumn-building-replay.py` を2ランドマークの見かけの一致から3種類の非共線ランドマークによる位置検査へ変更。カメラの回転/スケールを含む投影、第三点の残差10px以内、複数の似た解の競合を検査して保留できる。
- 合成画像（実画像やプレイヤー名を含まない）でランドマーク模様の移動・拡大を再現し、実際のテンプレート照合→投影位置→第三点遮蔽時の棄却までテスト。直接の座標入力での正常、2点のみ、非共線不足、別地点への偽一致、画面外投影の棄却もテスト。研究用CI `autumn-building-replay-review.yml` に分離。
- 手元のリプレイ①25.8秒・26.0秒を再解析した結果、旧方式で位置候補を出せていた箇所は3種類の一致を確認できず **0/2フレームで確定保留**。参考画像のアイコンと動画のマスは表示角度/人物遮蔽も違い、低い画像相関を閾値緩和で押し通さない。これは安全性向上であり認識率向上ではない。
- 08側の `applyRecognized` にも「3つ以上の異なるランドマーク分類」「第三点残差0〜10px」「視点競合なし」を要求するガードを追加。1マスずれを防ぐための条件で、まだreader.jsから画像判定結果を取得する実装はない。
- 目的は既存08への誤登録防止。特に「動画中の建築物の種類が参照スクショと同じ」という推測は使用禁止。外部画像や座標を追加せず、各フレームで現在の植物を独立に識別する工程は引き続き未実装。

## 追加検証：植物種類の独立分類（2026-11-16 朝）

- 提供済みゲーム画像から、人名/HUDを含めず植物付近だけを手動で12個切り出し、6種類（電流タンポポ・芳香ピーチ・花咲くサボテン・金運の木・仙果スターフルーツ・疾走キノコ）を含めた。
- `scripts/review-autumn-plant-crops.py` は、局所HSVヒストグラム＋上下左右の分布による類似度を計算する **ローカル研究専用** ツール。画像はユーザー環境の指定フォルダから読むのみ。画像本体・ユーザー名・切り出し一覧のファイル名をGitHubには保存しない。
- 各サンプルを除外して残り11個だけと比較する leave-one-crop-out 試験：**12例中、正しい候補3例、保留9例、誤採用0例**。保留理由内訳：未見の見え方7例、別種との近似2例。最も近い候補が間違っても閾値不足なら棄却する。
- 同じ元ゲーム画面からの少数サンプルに過ぎず、本番の感度・特異度や誤認率を保証しない。6種類が同じように認識できると主張しない。空鉢、戦闘演出、別角度の未見サンプルも未評価。
- `tests/test-autumn-plant-crops.py` で候補のみ・曖昧・未知の棄却、自己画像を使った過大評価を防ぐ除外評価を検証。研究用CIへ追加。
- **08のブラウザ本体には植物認識器をまだ接続していない。** 位置照合が未確定の間は画像の種類判定だけをもとに `applyRecognized` へ反映しない。次は有効な複数視点の正解座標と植物/空鉢のマスクを増やし、同じゲーム内の時間が異なるフレームで再現性を確認する。
