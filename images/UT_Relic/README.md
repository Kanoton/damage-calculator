# チップの元画像アップロード先

`UT_Relic_50042.png` のような、絵柄だけの元画像をこのフォルダへ置いてください。

## アップロード方法

- 抽出したPNGを、元のファイル名のままアップロードしてください。
- 透過・サイズ・余白はそのままで大丈夫です。切り抜きやチップ名へのリネームは不要です。
- ZIPでまとめている場合は展開し、中の画像をこのフォルダへアップロードしてください。
- 同名で内容が異なる画像は、上書きせず別名のまま残してください。あとで重複・差分を確認します。
- チップ以外か判別できないものが混ざっていても、未対応として整理します。ファイル名の数字だけでチップIDを決めません。

## アップロード後の対応づけ

チップ名・ツール内ID・効果の正本は [`csv/chip_list.csv`](../../csv/chip_list.csv) です。拡張子はCSVですが、現在の区切りはタブです。

画像との対応・レア度の正本は [`csv/chip_artwork_mapping.csv`](../../csv/chip_artwork_mapping.csv) です。こちらもタブ区切りです。2026-10-18に元画像75枚を既存チップ90件と絵柄で照合し、全件を対応づけました。利用者がCSVを手入力する必要はありません。

確認済みの例：

| 元画像ファイル | ツール内チップID | チップ名 |
| --- | --- | --- |
| UT_Relic_50042.png | 30 | ATM |

- 元画像番号の `50042` と、ツール内チップIDの `30` は別の番号です。
- 同じ絵柄を複数のレアリティで共有する場合は、1画像と複数のチップIDを対応づけます。レアリティはゲーム画面の背景・枠の色も併用します。
- 曖昧な対応は未確認として分け、確認してから読取用の見本へ反映します。

## レア度と更新方法

| rarity | rarity_color | 今回のチップ件数 |
| --- | --- | ---: |
| blue | 水色 | 28 |
| purple | 紫色 | 34 |
| gold | 金色（黄色） | 28 |

レア度は `images/chip_icon/` の既存トークンの枠色から自動分類しました。効果量・名前の強弱や元画像のグラデーションからは決めません。たとえば `UT_Relic_Attack.png` はID1（水色）・2（紫色）・3（金色）で共有します。絵柄とレア度を組にすると今回の90件は一意に区別できます。

- 対応表の列：`chip_id`（ツール内ID）、`chip_name`、`artwork_file`（本フォルダ内のファイル名）、`rarity`、`rarity_color`。
- 絵柄の対応は画像を比較して確認します。新しい画像番号だけからIDを推定しません。
- 対応表の検証：`python3 scripts/check-chip-artwork-mapping.py`。
- 既存アイコンの枠色からレア度を再分類：`python3 scripts/check-chip-artwork-mapping.py --assign-rarity`。色が曖昧なら停止します。
- 読取用の見本へ反映：`python3 scripts/build-screen-reader-chip-shapes.py`。元画像を黒背景に合成した4倍率の輪郭を追加し、枠色は対応表のレア度を使用します。元のトークン見本・実画面見本も保持します。
- 生成一致の確認：`python3 scripts/build-screen-reader-chip-shapes.py --check`。

チップ名・効果の `chip_list.csv` 自体の列や効果量は変えていません。ゲーム画面側で枠色・輪郭が十分見えない場合は保留し、対応表が完成していても全90件の実画面認識を保証するものではありません。

既存の [`images/chip/`](../chip/) は説明付き画像、[`images/chip_icon/`](../chip_icon/) は表示用の丸いアイコンです。今回の元画像は本フォルダで管理し、用途ごとに参照先を分けます。
