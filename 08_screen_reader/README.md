# 08_screen_reader — ゲーム画面読取の試作

`07_skill` から分離した独立版です。2026-10-12にmain `2dc3ad9` の計算・能力・入力・通常／横長／スマホUIを統合しました。元の `07_skill` は変更していません。
説明文は07の正本CSVから生成した `js/hover-text.js` を使用し、`check:08` で一致を確認します。詳細は [差分調査と統合記録](../docs/08-sync-20261012.md) を参照してください。
自キャラ・PT、HP、コイン、☆によるLv、ステータス画面の攻撃／防御、表示中ページの取得チップをブラウザ内で認識します。画像・映像を外部へ送信せず、APIキーやOCRサービスは使いません。

## 起動

リポジトリ直下で `python3 -m http.server 4173 --bind 127.0.0.1` を実行し、PC版Chrome／Edgeで `http://localhost:4173/08_screen_reader/` を開いてください。HTTPSで配信されたページも使用できます。画面共有はブラウザ・OSの許可が必要です。`file://` でも既存計算機と画像読取は使えますが、画面共有はlocalhost／HTTPSから試してください。

## 操作

画面読取の操作欄はページ下部の「画面読取」にマウスを重ねると開きます。クリックで開いたままにでき、再クリックまたはEscapeで閉じます。開いた操作欄は「ドラッグして移動」をつかんで自由に配置できます。矢印キーは10px、Shift＋矢印は40px移動。「位置を戻す」で標準位置・大きさへ戻り、「閉じる」は読取を止めずに操作欄だけ閉じます。右下の角で大きさも調整できます。本体のレイアウトは移動しません。移動力は誤読防止のため自動読取せず、手動操作と既存の計算を維持します。

1. 「ゲーム画面を指定」でゲームのウィンドウを選びます。
2. 「画面読取」でその瞬間を反映します。「画像を選ぶ」や画像の貼り付けでも試せます。
3. 「読取結果・調整」で判定結果を確認できます。「判定できた情報を反映」を外すと確認だけになります。自キャラが未判定なら自キャラを指定してください。1位を自キャラと決めつけません。
4. 「自動読取」をONにすると選択した間隔（初期0.5秒、0.25秒／1.2秒も選択可）を目標に監視し、2回連続して一致した情報を反映します。処理は重複しません。処理時間を含む開始間隔なので、重い処理では指定より遅くなります。静止画面の確認後は変化を待ちます。
5. チップ画面や別ページをゲーム側で開くと、見えたチップを対象キャラへ追加します。重複追加せず、見えなくなっても削除しません。映っていないページや他キャラの情報は保持します。
6. 「共有停止」で映像取得を終了します。反映済み情報は残ります。次の試合では「新しいゲーム」で自キャラ・PTのLv、HP、補正、チップを初期化し、読取を再開してください。マップ／モンスターのリセットは既存の操作を使います。

共有継続中は毎回のキャプチャ許可は不要ですが、再開時は再びウィンドウの選択が必要です。ゲームの最小化やツールをバックグラウンドに置いた時の取得／間隔はOS・ブラウザに依存します。認識誤りがあれば自動読取を止め、既存の手動編集で訂正できます。

## 認識範囲と見本

チップ元画像とレア度は [`csv/chip_artwork_mapping.csv`](../csv/chip_artwork_mapping.csv) に対応づけています。元画像75枚をチップ90件へ紐づけ、確認済みの実画面（未取得分は既存アイコン）の枠色から水色27件・紫色35件・金色28件を分類しました。しおりは素材の水色と実画面の紫色が異なるため、実画面の色と根拠を記録しています。同じ絵柄でも枠色と組み合わせて判定します。説明・更新手順は [`images/UT_Relic/README.md`](../images/UT_Relic/README.md)。元画像・確認済み実画面の輪郭見本を使い、色や輪郭が不鮮明な場合の保留、所有者・画面種別・連続一致の条件は維持します。全チップの実ゲーム画面での精度確認は未完了です。

読取の改善は、匿名化した実画面での回帰と、複数倍率・枠色・未知画像のテストを組み合わせます。未収録の表示差は失敗時のゲーム画面と期待結果があると確認できますが、チップごとに別々の報告でなく、複数キャラの一覧画面をまとめた動画や画像でも構いません。プレイヤー名・全画面はGitへ保存せず、必要領域だけをfixtureとして残します。

PTの顔は、初期の実画面見本（遠野ハンナ、カイセイ、アル、スミカゲ）に加え、対応表の35キャラ・128衣装画像から作成した照合データを使用します。実画面見本を優先し、未判定の場合に素材の顔領域を照合します。透明部分は比較せず、モンスター56画像を対象外判定にも使用し、似た候補との差が小さい場合は未判定にします。現在のHUD配置が基準です。全衣装の実ゲーム検証が完了したという意味ではありません。

自キャラ立ち絵は遠野ハンナ、大きいステータス画面は遠野ハンナ・カイセイに加え、ナンシーロー・ファニィ・橘シェリーの実画面見本を使用します。新しいPT判定から自キャラを推測しません。未判定のキャラ・位置は「認識用の見本を追加」で取得画面から登録できます。`111_Max`（スミカゲ）と `115_03`（ミサキ）は、比較可能な顔領域が小さいため素材照合から除外しています。未使用・判別不能の5画像も除外しています。

小さいチップ画面では自キャラの立ち絵が隠れるため、自キャラ判定を更新しません。最初に通常画面を読み取るか、自キャラを明示指定してから使用してください。チップ画面の選択タブを自キャラとは解釈しません。

チップは正本 `images/chip_icon/` の90種類を参照し、ATM・キャッシュカード（残高少ない）のゲーム内表示見本も同梱しています。類似アイコンや画像の違いで判定できない場合は、表示中のチップ位置と名前を指定して見本を追加できます。確信できない候補は追加しません。

読取位置は提供された1536×709のHUD配置が基準です。従来配置と、2026-10-08提供の左寄せ配置（遠野ハンナ／橘シェリー／ファニィ／ナンシーロー）の通常画面に対応しています。複数キャラとコイン・☆の判定から配置を毎回選択し、見本追加もその配置の顔・立ち絵を切り出します。2048×1152のステータス画面3枚で、カッターナイフ-ベーシック／キャッシュカード-残高少ない／大鉦を確認しました。中央のステータス画面は縦横比を維持して照合します。下側のチップ画面は追加の2048×1152画像4枚で、選択タブ・PTの持ち主・チップを検証しています。高さを基準に拡縮し、左端を基準に位置を合わせます。任意のHUD倍率や別配置を保証するものではありません。画像サイズは自動で合わせますが、異なる縦横比、HUD倍率・位置、ウィンドウ枠等では未判定になることがあります。「ゲーム範囲を指定」でプレビューをドラッグしてゲーム部分を切り出せます。汎用OCRや全35キャラの無調整認識が完成した版ではありません。

見本と範囲は `astral-08-screen-reader-profile-v1` にローカル保存します。見本はJSONで書き出し／読み込み可能です。試合の状態はページ内のみで、再読み込み時は保持しません。

画面で確認した最大HPは実測値を優先し、ATK／DEF／MOVEは既存計算との差を補正します。未読の数値は変更せず、チップ追加後に観測ステータスを合わせるため二重加算しません。所有コインは読取結果表と専用の内部状態に保持します。既存のコイン／スターコインのスタック・所持数操作とは自動連動せず、別項目の値を上書きしません。手札、CT、スキル状態は自動認識の対象外です。

## ラウンド・進捗・モンスターの同期

「マップ」で実際のマップ・難易度を選択し、操作欄の「選択中のマップへラウンド・進捗・モンスターHPを反映」をONにしてください。ページ起動時はOFFで、読取セッション開始時にONになります。OFF時はこの追加画像処理も実行しません。ラウンドは左上、進捗は中央上の青いマスを参照します。イベントアイコンで数字が隠れる場合は、左右の複数の数字の並びから推定します。自動読取では2回連続一致を待ちます。

操作欄にはモンスター読取のON/OFF・照合見本数（この版は29種類）・今回の認識数・連続一致数・反映保留数・処理時間・実際の開始間隔・取得サイズを表示します。「今回0体」は画像認識の未判定、「今回」が1体以上で「連続一致0体」なら自動反映の安定待ち、「反映保留」は選択マップや計算HPとの不一致です。モンスターの小さな文字・HP変化も静止判定へ含めます。高速設定でも文字が短時間しか表示されない時や、HUD倍率・位置の違いでは見逃します。名前とHPが見える場面でゲーム内リプレイを一時停止し、手動「画面読取」で確認すると、監視のタイミングと画像認識を切り分けられます。

進捗までの未実行イベントを正本CSVから一度だけ記録し、能力補正を適用します。読取による進捗追従では出現予定だけから個体を追加しません。個体は画像の名前・番号・HPが確認できた場合に追加します。手動イベント操作は従来どおり出現数を追加します。モンスターは名前＋管理番号（番号のないボスは名前）と現在／最大HPが揃い、選択中マップの最大HPと一致すると更新します。見えなくなっても削除・撃破扱いにはしません。同期の変更はマップの「戻す」で取り消せます。ラウンドの同期は絶対値の更新で、手動のターン終了操作によるCT・スタック減少を代行しません。

名前照合は29種類（ゴクチョーの通常／真相を別扱い）です：ゴクチョー、ゴクチョー【真相】、看守、大怪盗、グリーティーポット、ゼリーウィザード、さるのびっくり箱、さるの助手君、ゴリフランケンちゃん、キャンディビニャータ（映像ではピニャータ）、人工生命体―天崩、海賊王ガオー、海賊精鋭、海賊サメ、爆竹ゲロゲロ、指揮センター、獅子舞いガオー、雰囲気系ロボ、機械蛇龍、泥棒、学院警備官、ゼリーファイター、ゼリーガーディアン、魔法のティーポット。2026-10-13／14提供の魔法学院・水郷古鎮・夢想号・幽魂路地・異変図書館の動画から、プレイヤー名や全画面を含まない文字領域の見本を追加しました。通常個体は番号を必須にし、ボスは見本のboss指定で番号なしとして読みます。小さいHPの斜線も照合しますが、不明な数字・遮蔽された名前・似た候補は未判定にします。別場面の検証画像と部分遮蔽の回帰テストを含みます。提供画像のラウンド4／進捗4、ラウンド5／アイコン進捗5も維持しています。

動画別の確認結果と不足素材は [モンスター名照合の記録](../docs/08-monster-labels-20261014.md) を参照してください。機械蛇龍の一時的な0/0は反映しません。

ゴクチョーは通常形態も番号なしです。同じ名前でも最大HPが100未満なら通常、100以上なら真相の候補とし、反映前に選択難易度・手がかり・撃破数を含む正本の計算HPとの一致を必須にします。真相の確定後は既存の形態切替を一度だけ実行し、見えなくなったり古い通常形態の観測が来ても戻しません。ラウンド8だけでは切り替えず、赤い蝶や演出の画像認識は行いません。手がかり・撃破数・看守復活はまだ手動操作が必要で、これらが合わないHPは反映保留です。

再試運転にはPR #211のブランチ `codex/08-sync-reader-20261012` の更新版を使用してください。未マージのmainには追加見本が含まれません。ゲーム内リプレイは通常の画面共有で監視します。動画ファイル再生機能は追加していません。

これは全フレームや全モンスターの対応完了を意味しません。ゼリーウィザードは異変図書館の動画で全名の見本を追加しました。学院長代理・変なティーポットも今回の魔法学院動画では未確認です。消失からの自動撃破判定は未実装で、見えなくなった個体のHPを保持します。ボス撃破の素材は不要ですが、HP変動は引き続き確認します。期間限定の予選運動場・トーナメント運動場・決勝大会場は当面の素材確認対象から外し、登録情報を維持します。

## 構成・検証

### ミニキャラ画像の対応表

正本は `../csv/mini_character_mapping.csv` です。`images/UT_Hero_ProfilePhoto/` の194画像を1ファイル1行で収録し、キャラクター130画像（35人）、モンスター59画像、判別不能5画像に分類しています。モンスターと判別不能は `reader_target=対象外` です。画像番号とキャラIDは一致しないため、`character_id` を使用してください。モンスターの複数候補IDは `|` 区切りで保持します。

「認識用の見本を追加」でキャラを選ぶと、対応表から衣装違いも含む画像を表示します。Web配信時はCSV、`file://`・取得失敗・不正CSV時は同梱対応表を使います。PT認識用には、実画面に合わせた顔領域・透明部分のマスクを生成して同梱しています。自キャラ立ち絵やステータス画面は素材画像を流用せず、取得画面から見本を登録してください。

素材または対応表の変更後は、Pillowを使う `python3 scripts/build-screen-reader-profile-references.py` でPT照合データも更新します。`--check` で元データとの一致を検証できます。生成データは `file://` でも使用でき、監視中に画像を逐次ダウンロードしません。

## 読取と手動編集の併用

画面で読めた最大HPと、その時点の計算上の最大HPを保存します。その後の手動レベル変更・HPチップ取得／解除・最大HP効果では差分を反映し、次に最大HPを読めた時点で再び実測値へ合わせます。既存チップを画像から発見しただけでは、表示済みのHPへ二重に加算しません。最大HPが読めない画像では前の合計を保持します。自キャラ／PTの切替でも観測補正を引き継ぎます。手動訂正は自動読取を止めて行い、再開後に読めた値が手動値に優先します。

結果表には項目ごとに「今回」「保持」「安定待ち」「確認のみ」「反映保留」を表示します。読めなかった項目は計算機の値を「保持」として表示し、新しいキャラの候補へ別のPTメンバーの数値を混ぜません。チップ欄でも今回見えたものと取得済み件数の保持を区別します。

縮小（75%・50%）、軽いぼかし（0.5px・1px）、顔や数値の遮蔽は既存の匿名化画像から検証します。追加の実ゲーム画像や任意の画面配置の保証ではありません。

### PTの順番を確定して数値を追跡

「読取結果・調整」の「PTの順番を確定」で、ゲーム画面の上から4人を確認・訂正して「この順番で確定」を押します。自キャラが未判定でもPTだけ固定できます。自動読取では4人の名前が連続一致し、2人以上のコインとLvが安定すると自動で固定します。初期表示のミミを自キャラと誤解したまま反映を保留する場合も、この操作で実際のPTへ合わせられます。自キャラをPTの先頭とは仮定しません。

確定後は4人の顔を再判定せず、確定したHUD配置・順番に対応するLv・HP・コインを読みます。通常の自動読取の2回一致条件は維持します。HUDのコインとLvが2人以上で読めない画面では、固定した名前を根拠に数値を反映しません。ステータス画面の攻撃・防御とチップは従来どおり画面の対象キャラへ反映します。小さいチップ画面も確定順の選択タブに対応します。
