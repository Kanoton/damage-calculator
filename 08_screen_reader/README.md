# 08_screen_reader — ゲーム画面読取の試作

`07_skill` をコピーした独立版です。元の `07_skill` は変更していません。
自キャラ・PT、HP、コイン、☆によるLv、ステータス画面の攻撃／防御／移動力、表示中ページの取得チップをブラウザ内で認識します。画像・映像を外部へ送信せず、APIキーやOCRサービスは使いません。

## 起動

リポジトリ直下で `python3 -m http.server 4173 --bind 127.0.0.1` を実行し、PC版Chrome／Edgeで `http://localhost:4173/08_screen_reader/` を開いてください。HTTPSで配信されたページも使用できます。画面共有はブラウザ・OSの許可が必要です。`file://` でも既存計算機と画像読取は使えますが、画面共有はlocalhost／HTTPSから試してください。

## 操作

1. 「ゲーム画面を指定」でゲームのウィンドウを選びます。
2. 「画面読取」でその瞬間を反映します。「画像を選ぶ」や画像の貼り付けでも試せます。
3. 「読取結果・調整」で判定結果を確認できます。「判定できた情報を反映」を外すと確認だけになります。自キャラが未判定なら自キャラを指定してください。1位を自キャラと決めつけません。
4. 「自動読取」をONにすると約1.2秒間隔で監視し、2回連続して一致した情報を反映します。処理は重複しません。静止画面の確認後は変化を待ちます。
5. チップ画面や別ページをゲーム側で開くと、見えたチップを対象キャラへ追加します。重複追加せず、見えなくなっても削除しません。映っていないページや他キャラの情報は保持します。
6. 「共有停止」で映像取得を終了します。反映済み情報は残ります。次の試合では「新しいゲーム」で自キャラ・PTのLv、HP、補正、チップを初期化し、読取を再開してください。マップ／モンスターのリセットは既存の操作を使います。

共有継続中は毎回のキャプチャ許可は不要ですが、再開時は再びウィンドウの選択が必要です。ゲームの最小化やツールをバックグラウンドに置いた時の取得／間隔はOS・ブラウザに依存します。認識誤りがあれば自動読取を止め、既存の手動編集で訂正できます。

## 認識範囲と見本

初期キャラ見本は添付ゲーム画面の遠野ハンナ、カイセイ、アル、スミカゲのPTアイコンです。自キャラ立ち絵は遠野ハンナ、大きいステータス画面は遠野ハンナ・カイセイです。その他のキャラは「認識用の見本を追加」で、そのキャラが映っている位置と名前を選んで保存できます。

小さいチップ画面では自キャラの立ち絵が隠れるため、自キャラ判定を更新しません。最初に通常画面を読み取るか、自キャラを明示指定してから使用してください。チップ画面の選択タブを自キャラとは解釈しません。

チップは正本 `images/chip_icon/` の90種類を参照し、ATM・キャッシュカード（残高少ない）のゲーム内表示見本も同梱しています。類似アイコンや画像の違いで判定できない場合は、表示中のチップ位置と名前を指定して見本を追加できます。確信できない候補は追加しません。

初期の読取位置は提供された1536×709のHUD配置が基準です。画像サイズは自動で合わせますが、異なる縦横比、HUD倍率・位置、ウィンドウ枠等では未判定になることがあります。「ゲーム範囲を指定」でプレビューをドラッグしてゲーム部分を切り出せます。切り出しだけでHUD配置が合わない場合は、その解像度での読取位置調整が今後必要です。汎用OCRや全35キャラの無調整認識が完成した版ではありません。

見本と範囲は `astral-08-screen-reader-profile-v1` にローカル保存します。見本はJSONで書き出し／読み込み可能です。試合の状態はページ内のみで、再読み込み時は保持しません。

画面で確認した最大HPは実測値を優先し、ATK／DEF／MOVEは既存計算との差を補正します。未読の数値は変更せず、チップ追加後に観測ステータスを合わせるため二重加算しません。所有コインは読取結果表と専用の内部状態に保持します。既存のコイン／スターコインのスタック・所持数操作とは自動連動せず、別項目の値を上書きしません。マップの進捗、モンスター、手札、CT、スキル状態は自動認識の対象外です。

## 構成・検証

### ミニキャラ画像の対応表

正本は `../csv/mini_character_mapping.csv` です。`images/UT_Hero_ProfilePhoto/` の194画像を1ファイル1行で収録し、キャラクター130画像（35人）、モンスター59画像、判別不能5画像に分類しています。モンスターと判別不能は `reader_target=対象外` です。画像番号とキャラIDは一致しないため、`character_id` を使用してください。モンスターの複数候補IDは `|` 区切りで保持します。

「認識用の見本を追加」でキャラを選ぶと、対応表から衣装違いも含む画像を表示します。Web配信時はCSV、`file://`・取得失敗・不正CSV時は同梱対応表を使います。これは見本登録時のキャラ確認用です。プロフィール画像をそのまま認識特徴には追加していません。実ゲームのHUDでは拡大・切り抜き・背景が異なるため、認識用の見本は従来どおり取得画面から登録してください。

CSV修正後は `python3 scripts/build-mini-character-mapping.py` で同梱データを更新し、`python3 scripts/build-mini-character-mapping.py --check` で画像の網羅性、重複、ID・名前、参照画像、同梱データとの一致を確認します。列の意味と未確定項目は `../docs/mini-character-mapping.md` を参照してください。

- `js/screen-reader.js`: 共有／画像入力、監視、安定判定、結果表示、見本管理
- `js/screen-reader-vision.js`: 画像照合、数字形状照合、☆判定、画面種別・対象判定
- `js/screen-reader-references.js`: 生成済み特徴（フル画像やプレイヤー名を含まない）
- `js/character.js`: `ScreenReaderCharacterBridge` から既存自キャラ・PT状態に反映
- `scripts/build-screen-reader-references.py`: 正本チップ画像と提供画面から特徴を再生成（Pillowが必要）
- `tests/fixtures/screen-reader/`: プレイヤー名、チャット、マップを除去した読取領域だけのテスト画像

`npm run check:08`、`npm run test:08` を使用します。既存の `npm run check:07`、`npm run test:07`、`npm run test:06b` も維持しています。
